# Your Legacy Is Not Mine

![Legacy code and software evolution](https://images.unsplash.com/photo-1461749280684-dccba630e2f6?ixlib=rb-4.0.3&ixid=M3wxMjA3fDB8MHxwaG90by1wYWdlfHx8fGVufDB8fHx8fA%3D%3D&auto=format&fit=crop&w=2069&q=80)

When I say "legacy code" what year do you think of? Is there a specific pattern or practice that you remember and hate? Is there a specific version of a language, framework or server that you can't stand?

Perhaps "legacy" just means other people's code. Perhaps you have been lucky enough to only do greenfield development in your career so far. Is "legacy" not a bad word to you?

## The Good Legacy

Perhaps you work on a system that has "good bones". Each day you start work and find useful refactors that make things better but don't break all the tests. You have good test coverage and a database that is performing well. That is not always the case.

## The Bad Legacy

How would you handle working on a platform that needs patched, is complicated, obfuscated, horrible to maintain, has been around since the 80's or 90's? It's not easy. You want to quit every day. You can't code good enough or fast enough to make anyone happy. Any success only lasts a few days.

## My Approach

Here's what I've learned about dealing with legacy systems:

1. **Don't Take It Personally**: The mess wasn't created by you, and fixing it isn't your personal failing
2. **Small Improvements**: Make tiny, incremental improvements rather than trying to rewrite everything
3. **Document as You Go**: Leave breadcrumbs for the next developer (who might be you)
4. **Build Tests**: Add tests around the areas you're working in, even if the rest of the system doesn't have them
5. **Know When to Walk Away**: Sometimes the kindest thing you can do for yourself is find a better codebase

## The Reality

Working with legacy code is part of being a professional developer. The key is learning how to do it without losing your sanity or your passion for programming.

Your legacy code problems are not my legacy code problems, and that's okay. We're all fighting different battles in different codebases. The important thing is that we keep fighting to make things a little bit better, one commit at a time.
